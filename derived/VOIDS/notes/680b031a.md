- Run: T2S (evo-t2), boot `792e909d`, NPU-1 cell, `MAX_PROMPT_LEN` 1024.
  The run stays. This note does not delete it.
- Classification: UNGUARDED. The summary has no `armed` or `UNGUARDED`
  field. The opening log line is
  `[c2_canary] index=0 after_probes=-1 armed=False`.
- What that line is: `TtftSloCanaryGuard.run_canary` prints it before the
  canary cell. `after_probes=-1` is the opening call. `armed=False` is the
  gate's starting state.
- What the cell is: `gpu_only_f16`, `load_sequence` GPU, `generate_device`
  GPU, `n_cached=4000`, `delta=400`, `RESIDENT`
  (`tools/ttft_slo_canary.py`, `configs/delta_n.yaml`). It is a second
  pipeline. The NPU pipeline loaded at 1024 is not the pipe that cell uses.

  `opening()` once, stores the plan fragment, and drops the guard. It never
  calls `after_probe`. The gate cannot arm. The NPU probes still ran.
  `arm()` then wrote `UNGUARDED: false` on the plan, and the summary writer
  copied neither field. `finalize_or_refuse` was not called.
- The GPU cell's own classification is `work/canaries/canary.0.json` on the
  host. A non-OK opening cell does not abort before calibration completes,
  so completion of the NPU probes does not say the GPU cell was OK.
